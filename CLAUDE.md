# frozen-duckdb

Zero-compilation DuckDB for Rust via the Builder Sub-Crate Pattern:
`frozen-duckdb` (ultra-thin drop-in duckdb-rs replacement),
`frozen-duckdb-builder` (acquires/caches the mega-library in
`~/.frozen-duckdb/cache/`), `frozen-duckdb-sys` (FFI layer). Crate version
mirrors the bundled DuckDB version: 2.0.0-dev.

## Agents

Never dispatch the built-in generic agents (`general-purpose`, `claude`).
Only use agents defined in `.claude/agents/` (bench-runner, gate-author,
milestone-doc, release-op) plus read-only Explore and Plan. Subagent
prompts always carry the absolute repo path (this repo's root).

## Commands

```bash
make verify          # full gate: verify-gates + ggen receipt verify
make verify-gates    # bash scripts/verify-gates.sh
make sync            # ggen sync — Makefile is GENERATED; edit ggen.toml schemas
make gates           # sync + genesis-check
make genesis-check   # generated-surface drift check
```

The Makefile is generated by `ggen sync run` — edit the ggen.toml schemas,
never the Makefile. `make sync` / `make gates` re-render it.

### Test ladder

```bash
cargo build                       # workspace build
cargo test -p frozen-duckdb       # main-crate test suite
cargo clippy --workspace -- -D warnings
cargo fmt --check
cargo test --workspace            # full workspace tests
```

## Layout

- `crates/frozen-duckdb/` — main crate; drop-in `duckdb` replacement
- `crates/frozen-duckdb-builder/` — release download / local-compile
  fallback / cache; `vendored-headers/` carries DuckDB 2.0.0-dev
  `duckdb.h`/`duckdb.hpp` so bindgen works offline
- `crates/frozen-duckdb-sys/` — FFI bindings and linking
- `scripts/` — `build_duckdb_optimized.sh`, `download_duckdb_binaries.sh`,
  `release_checklist.sh`, `verify_publish_receipt.py`
- `gates/dry-run-publish/` — publish dry-run gate (SHACL shapes + domain)
- `docs/sjira/v<version>/` — milestones (newest dir = active window)
- `.doc-surface.toml` — generated-surface config; `generated/` outputs are
  never hand-edited

## Working conventions

- Git: `git commit -F <file>`, never inline `-m`. No rebase, no force-push;
  merges only.
- Receipts embed real command output, not summaries.
- One canonical checkout per repo; no worktrees. Lane builds use
  `CARGO_TARGET_DIR=target-lane<N>`; the coordinator deletes lane target
  dirs at integration before the final commit.
- Vendored DuckDB headers live in
  `crates/frozen-duckdb-builder/vendored-headers/`.
- Current standings: `docs/sjira/v2.0.0-dev/DEFINITION-OF-DONE.md`;
  known divergences: `KNOWN_DIVERGENCES.md` (single source of truth —
  do not restate standings or numbers here).
- Known open item: no git tag or GitHub Release exists yet for 2.0.0-dev
  (pre-tag staging from upstream main), so builds fall back to compiling
  DuckDB locally from the pinned upstream source SHA — see README.md.
