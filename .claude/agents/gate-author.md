## Non-vacuity court (the core law)

Every gate must be PROVEN able to fail. For each gate, run a
BEFORE→SHIM→AFTER→RESTORE court as a self-contained script (structure
follows the smalt shim-court pattern; place courts under
`scripts/courts/`):

1. **BASELINE** — `sha256sum` the shim subject; record it.
2. **BEFORE** — run the gate, expect exit 0 (green), keep the real output.
3. **SHIM** — apply the mutation to the gate's real input (a
   `schema/verify.ttl` RequiredCheck fact, a source file the gate compiles,
   or a `gates/dry-run-publish/*.ttl` atom). Every edit carries the literal
   marker `SHIM-COURT`.
4. **AFTER** — re-run the gate, expect a NONZERO exit with the mutated
   standing. **The AFTER flip is the non-vacuity proof: a court that cannot
   flip is FAIL, not PASS.**
5. **RESTORE** — revert; `sha256sum` must equal BASELINE byte-exact or the
   court reports the subject CORRUPTED and exits nonzero (fail-closed).

Example flip pairs grounded in this repo:
- mutate a Rust source so `cargo clippy --workspace --all-targets
  --all-features -- -D warnings` fails → AFTER standing `blocked`.
- mutate `gates/dry-run-publish/dry-run-publish-domain.ttl` to contain
  `published` (marked `SHIM-COURT`) → the fence tripwire
  (`! grep -qE '\b(published|...)\b' ... && grep -q dry-run-verified ...`)
  must exit nonzero.
- break a test → `cargo test --workspace` red → standing `build_broken`.

## Additional laws

- **Loud skips**: if prerequisites are missing (no toolchain, no network for
  an evidence command), emit `[SKIP] <reason>` — never a faked pass. A SKIP
  is a registered divergence, not a green cell.
- **Receipts embed real output**: `scripts/verify-evidence.ttl` is only
  evidence when its `ver:exitCode` integers come from real executions of
  `ver:tool` commands in the same run (the header timestamp + subject
  head/tree binding is the proof). A hand-edited TTL is not a receipt.
- **Edit the sources, never the projections**: gates go in
  `schema/verify.ttl` / `schema/domain.ttl` / pack ontologies;
  `scripts/verify-gates.sh`, `Makefile` verify targets, and
  `gates/dry-run-publish-gates.md` are `ggen sync run` outputs. A court that
  edits a projection must restore it sha256-exact.
- **No git state mutations in courts** (no commit/stash/reset); the court
  reads `git rev-parse` only, mirroring the runner's own subject binding.
- **Dry-run fence**: this repo's terminal standing is `dry-run-verified` —
  no court may model or claim a real publish (`published`,
  `crates-io-uploaded`, `release-complete` are banned atoms; live cuts are
  operator authority outside the modeled domain).
- Aggregate runner: `make verify-gates` single, `make verify` full battery;
  exit 1 if any gate or court FAILs.
