# Gap detection in frozen-duckdb

This document previously described a KCura-era gap-detection suite
(`ci_gate.sh`, `ci_gates.sh`, `fake_guard.sh`, `scan_fakes*.sh`,
`redteam_probe.rs`) and a "KCura codebase". Those scripts and that codebase
do not exist here. This revision reconciles the document with current
reality (TR6 2026-09-21 + G5 2026-09-21); the removal record lives in
`scripts/README.md` and the ticket History files under `docs/sjira/v26.9.21/`.

## What exists today

### `rg_sweep.sh` — informational pattern sweep (KEPT-FIXED by G5)

```bash
./scripts/rg_sweep.sh | tee sweep.log
```

What it checks now:

- Stub and placeholder tokens across the tree
  (`unimplemented!`, `todo!`, `panic!`, `TODO`, `FIXME`, `XXX`, `dummy`,
  `fake`, `stub`, `placeholder`)
- Telemetry/OTEL integration probes
- Governance/audit scaffolding tokens
- The real frozen-duckdb FFI surface (`frozen-duckdb-sys` bindgen output,
  plus a check that no hand-written `extern "C"` lives outside it)

It is informational only: it never fails a build, and its "GAP:" lines are
candidates to review, not verdicts. G5 trimmed its former kcura-era sections,
whose `rg` paths pointed at `crates/kcura-*` crates that were never part of
this repo, so ~80% of the output was permanent false warnings.

### Standing gates that do fail builds

- `make gates` — `ggen sync run` + `make genesis-check`
  (reconciliation manifest: `docs/GENESIS.md`)
- `scripts/verify-gates.sh` — GENERATED by `ggen sync run` (do not edit;
  edit `schema/verify.ttl` and re-render); runs every required check and
  records real exit codes in `scripts/verify-evidence.ttl`
- `.github/workflows/ci.yml` — fmt/clippy/build/test/examples
  (there are no de-fakery jobs; the former README claimed jobs named
  `de-fakery-scan`, `redteam-probe`, `semantic-coverage` that were never
  present in this workflow)

## If you need a fake-pattern gate again

capability, compose or extend an admitted family, and land it as pack facts
(ontology + gate) that render the check — not as loose shell scripts here.
